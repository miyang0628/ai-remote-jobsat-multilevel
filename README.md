# ai-remote-jobsat-multilevel

Replication code for a multilevel study of how **work arrangement (in-person /
hybrid / remote)** moderates the association between **AI tool use** and
**job satisfaction**, using the Stack Overflow Developer Survey (2024 & 2025).

> **Anonymized for peer review.** This repository omits author names,
> affiliations, and acknowledgments in accordance with the anonymous submission
> policy of the target venue. Author information will be added after review.

## Summary of findings

- **Main effect (H1):** AI use is positively but weakly associated with job
  satisfaction in both years (small effect on the 0–10 scale).
- **Moderation (H2):** Work arrangement does **not** moderate the AI–satisfaction
  link. The null replicates across 2024, 2025, a robustness sample, and multiple
  minimum-country-N thresholds.
- **Country level (H3):** No meaningful between-country variation in the AI
  slope; the intraclass correlation for job satisfaction is very low (~1–2%).
- **Exploratory (intensity):** When AI use is measured by *frequency* (2025 only),
  the frequency–satisfaction slope increases from in-person to hybrid to remote.
  This pattern is sensitive to the equal-interval coding of frequency and cannot
  be replicated in 2024 (no frequency item), so it is reported as exploratory.

## Data

Raw survey files are **not included** in this repository (size and licensing).
They are publicly available from the official source. Download the results CSVs
and place them in `data/raw/` as `survey_2024.csv` and `survey_2025.csv`:

- Official portal: https://survey.stackoverflow.co/
- Survey data are licensed under ODbL 1.0 (contents under DbCL 1.0).

Notebook `01_download.ipynb` will attempt the download automatically and verify
that each file is a real CSV (not a Git-LFS pointer). If automatic download
fails, obtain the "Data (CSV)" archive from the portal manually.

## How to reproduce

Run the notebooks in order from the `notebooks/` folder:

1. `01_download.ipynb` — ensures `data/raw/` contains both survey CSVs.
2. `02_recode.ipynb` — writes analytic samples to `data/processed/`.
3. `03_analysis.ipynb` — fits all models, writes tables and figures to `results/`.
4. `04_descriptives.ipynb` — writes Table 1, VIF, ICC, and sensitivity analyses to `results/`.

Each notebook adds `src/` to the path and imports the shared functions, so the
recoding and modeling logic lives in one place and is reused across notebooks.

## Method notes

Analyses are individual-level observations nested in countries (two-level
random-intercept models; a random-slope specification is used to test H3).
Three practical points are handled in `src/models.py`:

1. the continuous control is standardized (helps random-slope convergence);
2. all models compared by likelihood-ratio tests share one optimizer;
3. degrees of freedom for LRTs are computed from parameter counts.

Years are analyzed **separately** (item wording differs across 2024 and 2025)
and compared as a replication, rather than pooled.
